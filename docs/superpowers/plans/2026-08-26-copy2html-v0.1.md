# Copy2HTML v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a public, frontend-only Copy2HTML v0.1 that converts Word clipboard content into sanitized, validated HTML ready to paste directly into Liferay, with Smiles as the default preset pack.

**Architecture:** Next.js client application with a Tiptap editor, a deterministic clipboard normalization pipeline, generic serializer/sanitizer/validator modules, isolated preview, and versioned preset packs. Smiles-specific behavior lives exclusively under `src/preset-packs/smiles`, while user-defined presets persist through a tested `localStorage` abstraction.

**Tech Stack:** Next.js, TypeScript, Tailwind CSS, shadcn/ui, Tiptap, DOMPurify, Zod, Vitest, Testing Library, Playwright

**Spec:** `docs/superpowers/specs/2026-08-26-copy2html-v0.1-design.md`

## Global Constraints

- Public application with no authentication.
- 100% client-side processing for copy, clipboard content, presets, and generated HTML.
- Smiles is the default active preset pack, but editor, clipboard, sanitizer, serializer, and validator must remain generic.
- Liferay-compatible HTML is the only v0.1 output mode.
- User-created presets persist in `localStorage`; no backend or database.
- Final preview and clipboard output must use sanitized HTML only.
- No copy content, clipboard payload, generated HTML, custom preset values, credentials, or operational secrets may be logged or sent to analytics.
- Historical reference data must be sanitized before entering the repository.
- Critical transformation logic follows TDD.
